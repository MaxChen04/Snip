**Fix before merging the affected PRs:**

1. **#59: simplify recovery to unique matches and explicit unresolved states.**

   The resolver chooses the nearest section with the same label/kind, can fall back to position for a header/hero/footer, and takes the first matching animation. Duplicate page paths collapse to one entry. It then reports that every item was found and tells the agent to use the new IDs. A recaptured page with repeated labels or a replaced hero can therefore redirect the agent to a different design while appearing certain. An actual helper probe with duplicate paths selected the last page and reported success.

   The same success summary excludes requested-view failures: a missing mobile screenshot or unavailable dark theme can still produce a next call, even when availability flags are false. A synthetic missing-mobile/dark case confirmed this contradiction.

   Keep direct-ID lookup, then accept only a unique sufficiently supported recovery match. Return ambiguous candidates or unavailable view explicitly, and suppress automatic next calls for them. Removing nearest/position fallbacks makes this code smaller and its promise clearer. Ask the user only when the intended item cannot be established. [Matching](https://github.com/MaxChen04/Snip/blob/a8f2ed09f671968eb92708692381eb2ade3bf4ae/web/shared/selection.ts#L79), [view handling](https://github.com/MaxChen04/Snip/blob/a8f2ed09f671968eb92708692381eb2ade3bf4ae/web/shared/selection.ts#L113), [success summary](https://github.com/MaxChen04/Snip/blob/a8f2ed09f671968eb92708692381eb2ade3bf4ae/web/shared/selection.ts#L180).

2. **#60: give old-capture preparation an owned lifecycle.**

   A legacy styles read schedules compression and an R2 write through waitUntil. That writer is absent from the upload tracking used by deletion cleanup. Deleting a reference while the write is pending can finish cleanup and remove its tombstone; the background operation then writes a file under the deleted capture and updates zero page rows.

   This was reproduced with the actual MCP handler, database deletion/cleanup functions and isolated Miniflare D1/R2: pause the parts write, delete and clean up the reference, release the write, then observe an orphaned object with no page or cleanup tombstone. The reproduction establishes the race locally, not its frequency on hosted Cloudflare.

   Use coordinated derived-file writer admission and cleanup, or a retryable preparation job with explicit ownership. The simplest narrower alternative is to optimize new captures and retain the existing fallback for old captures until recapture; that trades immediate optimization of old libraries for fewer background states. The existing beginUpload helper cannot be reused unchanged because it admits only actively capturing jobs. Concurrent first reads also need a policy to avoid duplicate preparation. [Background write](https://github.com/MaxChen04/Snip/blob/320f6480a89691d995cee08153854ecb756e4c58/web/worker/mcp.ts#L631), [cleanup protocol](https://github.com/MaxChen04/Snip/blob/320f6480a89691d995cee08153854ecb756e4c58/web/worker/db.ts#L565).

3. **#60: preserve absolute omission indexes in paginated style results.**

   The new path slices the requested elements, then calls bounded(items, 0, limit). An oversized element on the page starting at offset 5 is reported as omission index 0, while the original-file fallback reports index 5. This was reproduced through the actual handler. Preserve the filtered-result offset when producing omission markers and test parity at nonzero offsets. It is a focused contract fix. [Affected call](https://github.com/MaxChen04/Snip/blob/320f6480a89691d995cee08153854ecb756e4c58/web/worker/mcp.ts#L597).

**Architecture improvements with the largest benefit:**

4. **#58 and #61: apply the small-read approach consistently.**

   Search retrieves complete page rows and complete reference rows, including token JSON that the final search response does not use. Motion-profile reads call db.getReference, loading every page and animation even when page_id requests just one page. That new call remains expensive after #60 merges because it bypasses the targeted readers introduced there.

   In a synthetic search probe, adding 26 KB of token data per page increased database result bytes from 11,567 to 193,896 for the same seven page hits, while the MCP response stayed exactly 12,371 bytes. Reference search showed the same pattern: 4,202 to 108,390 database result bytes with an unchanged 6,105-byte response. These measure local serialized results, not hosted latency or billable capacity.

   Use explicit lightweight search projections, a reference-record lookup for the merged profile, a single-page lookup for page scope, and a small indexed recording query. Share these readers across tools so adding a field to a page row does not silently make every search heavier. [Page search projection](https://github.com/MaxChen04/Snip/blob/9e535884729e80eb2d811c9003553f9b9e7bbb12/web/worker/search.ts#L167), [reference search projection](https://github.com/MaxChen04/Snip/blob/9e535884729e80eb2d811c9003553f9b9e7bbb12/web/worker/search.ts#L234), [motion read](https://github.com/MaxChen04/Snip/blob/74d9d5c249cf9faefde00884d9d4345fe371e57f/web/worker/mcp.ts#L697).

5. **#58 and #61: reuse one response-budget and continuation policy.**

   The motion tool returns its profile directly, silently takes the first 12 recordings, and has no continuation. Profile construction also caps several groups without reporting what was omitted. Count limits do not bound variable-length strings or serialized bytes.

   Search now repeats a reference note on every matching page. Using the supported 2,000-character note limit, a 20-hit fixture produced 40,000 bytes of repeated notes and a 106,375-byte complete response, including the text/structured representations. This is a local size measurement, not proof that a particular client rejects the result.

   Return a bounded motion overview and paginated groups with totals, omission reasons and continuation. For search, carry reference-level intent once per reference or use a bounded preview with an explicit way to retrieve the complete note. Any byte limit must advance the cursor by the items actually delivered. The goal is a shared contract, rather than another bespoke pagination scheme. [Motion output](https://github.com/MaxChen04/Snip/blob/74d9d5c249cf9faefde00884d9d4345fe371e57f/web/worker/mcp.ts#L702), [search output](https://github.com/MaxChen04/Snip/blob/9e535884729e80eb2d811c9003553f9b9e7bbb12/web/worker/mcp.ts#L717).

6. **#61: preserve selection scope and distinguish observation from interpretation.**

   The copied prompt adds a reference-wide motion-profile call whenever motion exists on the reference, even for one selected page. That can supply unrelated pages' motion while the prompt also says to fetch only selected items. Use the selected page scope, or selected animations, and request site-wide motion only when that is the user's selection. [Prompt](https://github.com/MaxChen04/Snip/blob/74d9d5c249cf9faefde00884d9d4345fe371e57f/web/src/lib/agent-prompt.ts#L57).

   The tool describes the result as exact, but stagger detection uses timing tolerances, some curve names are classifications, and matching a duration/easing to a CSS variable by equal value does not prove the original declaration used that variable. Preserve observed browser timing as observed data; label inferred staggers/curve descriptions and equal-value token candidates accordingly. This helps agents explain what they know without overstating the site's design intent. [Claim](https://github.com/MaxChen04/Snip/blob/74d9d5c249cf9faefde00884d9d4345fe371e57f/web/worker/mcp.ts#L682), [token association](https://github.com/MaxChen04/Snip/blob/74d9d5c249cf9faefde00884d9d4345fe371e57f/capture/src/motion-profile.ts#L118).

   The new before-load browser test failed locally and in three focused reruns. An instrumented run measured starts at 45, 51, 91 and 131 ms: gaps of 6, 40 and 40 ms. The first timer was late; only two of three gaps met the heuristic, below its 70% threshold. This is a demonstrated timing-sensitive fixture and a limitation under scheduling jitter, not proof that all script-driven staggers fail. Make the inference fixture deterministic, retain a separate realistic jitter case, and expose uncertainty. Simply loosening the threshold can introduce false positives.

Other focused follow-ups: token-only copied selections in #59 need a revision check before trusting inline values; their current trigger depends on another fetched result. Also align/chunk copied selections with the resolver's limits of 100 pages/animations and 50 sections. A crawl can contain 200 pages. #60 additionally deduplicates keyframe names in summaries compared with the base behavior; preserve or document that contract change. These are narrower than the architecture changes above.

**#57 is appropriately small.** The saved note is quoted, omitted when blank, and covered by focused tests. No concrete issue was found in that PR.
