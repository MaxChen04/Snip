# Snip 0.1.36: first beta release notes

**Status: prepared for the next beta; not yet published.** These notes describe changes on `main` since the source-only `v0.1.0` release. They do not announce an available installer or a fully validated stable release. Check [GitHub Releases](https://github.com/MaxChen04/Snip/releases) for published downloads.

Snip turns websites into a private design-reference library that you and your agents can use. This beta adds boards, image uploads, richer captures and more precise agent access, alongside capture recovery and cloud-management improvements.

## Browse and organize references

- Explore an infinite canvas or choose a scrolling grid. Filter websites, pages, sections, animations and images; the selected gallery mode is remembered per browser.
- Add links from the dock's **+** popover, choose **Landing page** or **Whole site**, and set a crawl limit. Upload images from the same popover or by drag-and-drop.
- Arrange references on boards with sticky notes, groups, saved positions and layer controls. Uploaded images receive thumbnails and color palettes.
- Inspect sections, colors and type, and motion without losing your place. Desktop/mobile, light/dark and static/live controls use the available captured views.
- Search hints and saved-site suggestions make filtering clearer. Capture-popover input focus, mobile layout and stale suggestions were corrected.
- Notes explain why you saved a reference. They are searchable and included in copied agent prompts. Website ZIP exports bundle the captured material.

## Capture more useful visual evidence

- Split pages into named sections and crop them for closer inspection. Moving sections can receive short WebM clips, played over the captured screenshot.
- Capture alternate light/dark appearances when the site changes with the requested color scheme. Preserve the selected look in the inspector.
- Record scroll and hover animation as WebM, with GIF fallback for compatibility. Each animation also has sampled frames and a contact sheet for models that cannot watch video.
- Log CSS transitions, animations and Web Animations. A bounded motion profile describes timing, easing, staggers and detected techniques, distinguishing observations from inference and pixel-only motion.
- Improve captures of in-view reveals, script-driven hover effects, delayed repaints, Trusted Types pages and content hidden by browser rendering optimizations. Keep live clips aligned with their starting screenshot and section bounds.
- Show pages as they arrive, with progress and loading cards. Improve crawl URL selection, shrink thumbnails, store site icons locally, and gzip HTML/style payloads.

## Recover interrupted work

- Pause, resume or stop crawls at page boundaries without discarding completed pages. Saved checkpoints preserve progress across interruptions.
- Per-claim leases and capture-attempt checks reject stale writes. Root HTTP failures are reported clearly; child-page failures can retain partial crawl results and warnings.
- Failed captures get a diagnosis and Retry. Source installations can repair a missing Playwright browser; bundled releases use their packaged browser.
- Re-capture confirms replacement of saved pages. Deletion, cancellation, retry and late-result paths have additional regression coverage.

## Give agents precise, bounded context

- MCP Tasks let compatible clients run captures in the background; other clients can use `wait_for_capture` with bounded waits.
- Search includes saved notes, section labels and captured page text. Agents can request just an overview, page list, animation list or token group rather than always reading an entire reference.
- `get_page_styles` returns valid bounded style data instead of a truncated JSON fragment. `get_motion_profile` exposes the captured motion evidence.
- Copied prompts retain viewport, theme, section and capture-run provenance. `resolve_selection` finds references again after recapture and reports changed or stale selections.
- MCP responses include structured data, continuation information and signed file URLs. Legacy full-reference reads and older GIF captures remain supported.

## Local first, optional cloud

- Enable a private cloud library in your own Cloudflare account through Settings or the CLI. Guided provisioning creates resources, copies the library and checks the result; human authorization steps remain explicit.
- New cloud setups use passkeys and one-time owner links. This version supports one owner on their devices, not multi-user collaboration. Existing GitHub-based installations retain their compatibility path.
- Manage devices, sign out everywhere (including connected agents), copy a cloud library back, or detach without implicitly deleting cloud data.
- Cloud capture still runs on your Mac. Other devices show **Waiting for the capture agent** when it is unavailable.
- Packaged cloud updates drain capture work, verify deployment and only then resume. Failed or cancelled updates remain paused for that session.
- Setup now forwards the selected Cloudflare account correctly; a failed preflight check does not mutate setup state. Storage usage caching and OAuth rate limits reduce unnecessary cloud work.

## Updates, security and maintenance

- `npm run update` provides a resumable source-update path with database backups and migrations. The app can notify source installations when `main` changes. Updates distinguish processes belonging to different checkouts.
- Snip Dev is isolated from the normal app, with its own profile, port and test library. Nightly builds have a separate prerelease channel; signed stable installation has separate acceptance requirements.
- Capture network guards validate destinations and DNS before connecting; private-network access remains opt-in. Writes have same-origin protections, uploads are checked by actual file type, and capture protocol compatibility is enforced.
- Dependency and CI updates include Electron 45.3.0, Playwright 1.65.0 and Wrangler 4.160.0, plus consolidated duplicated code and removal of unused components.
- Expanded regression coverage includes capture lifecycle, cloud setup, migrations, MCP budgets, modal/focus behavior and packaging. Test timing corrections retain the behavioral assertions rather than skipping checks.

## Upgrade notes

Use the [source update instructions](../../README.md#updating) for a checkout-based installation. Keep your library and its configuration together, and allow the updater to back up and migrate the database. Update the Worker and capture agent together: this code uses capture protocol 4.

Applied migration filenames must not be renamed. In particular, `0016_page_text.sql` and `0017_style_parts.sql` are retained for installations that applied the earlier feature branches. See the [landing plan](../release-landing-plan.md) for deployment sequencing and migration checks.

## Beta limitations and validation boundary

Local capture and library workflows have passed automated regression checks and representative live-site testing. That does **not** establish every deployment or update path:

- Real hosted-library setup/upgrade, real-device passkey enrollment and a signed A→B native update still require their release acceptance checks.
- The canvas shows up to 400 items per feed. Search to locate older items. Keyboard navigation can require recentering after panning far into repeated canvas regions.
- Sites behind authentication or bot challenges may capture the page the browser actually receives. Captures are evidence, not a guaranteed pixel-perfect replay of every website.
- Live clips, section detail and alternate themes depend on the source page and capture budgets; older captures may need a recapture.

See [Known limits](../../README.md#known-limits) and [desktop release requirements](../../desktop/RELEASING.md). No signed installer or proven native-update path is implied by this document.
